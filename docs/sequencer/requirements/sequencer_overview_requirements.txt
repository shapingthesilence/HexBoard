HEXBOARD SEQUENCER OVERVIEW REQUIREMENTS

ID: SEQ-CORE-001
Title: Separate Sequencer Mode
Status: Active
Area: Core
Priority: High

Requirement:
The project shall provide a Sequencer mode that is separate from Keyboard mode.

Details:
- Sequencer mode shall not replace normal Keyboard mode.
- The user shall be able to return to Keyboard mode from the Sequencer menu.


ID: SEQ-CORE-002
Title: Single Track Design
Status: Active
Area: Core
Priority: High

Requirement:
Sequencer mode shall operate as a single-track sequencer.


ID: SEQ-CORE-003
Title: Thirty-Two Step Capacity
Status: Active
Area: Core
Priority: High

Requirement:
Sequencer mode shall provide 32 editable steps.

Details:
- The active playback length may be less than 32.
- All 32 steps shall remain editable even if fewer steps are active in playback.
- Step LEDs beyond the active playback length shall stay dark until those steps
  are brought back into the active range.


ID: SEQ-CORE-004
Title: Per-Step Note Capacity
Status: Active
Area: Core
Priority: High

Requirement:
Each step shall store up to 6 notes.

Details:
- Stored notes shall use tuning-relative pitch-step values instead of raw MIDI
  note numbers.


ID: SEQ-CORE-005
Title: Per-Step Length Storage
Status: Active
Area: Core
Priority: High

Requirement:
Each step shall store its own note length value.


ID: SEQ-CORE-006
Title: Per-Step Velocity Storage
Status: Active
Area: Core
Priority: High

Requirement:
Each step shall store its own velocity value.


ID: SEQ-CORE-007
Title: MIDI And Onboard Synth Playback
Status: Active
Area: Core
Priority: High

Requirement:
Sequencer mode shall be able to play through either MIDI output or the onboard
synth.


ID: SEQ-CORE-008
Title: Flash-Based Sequence Storage
Status: Active
Area: Core
Priority: High

Requirement:
Sequences shall be stored in onboard flash using the project sequence file
system.


ID: SEQ-CORE-009
Title: Current Behavior Documentation
Status: Active
Area: Core
Priority: Medium

Requirement:
The requirements documents shall describe the current intended Sequencer
behavior as directly as practical.

Details:
- Removed older behavior should not be mixed into active requirements.
- Manuals, layout docs, and requirements should be kept aligned.
